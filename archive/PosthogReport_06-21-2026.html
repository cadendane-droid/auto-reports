What this means

Sample sizes are tiny (1–3 active users/week) — read every number below as directional, not statistical.
Strongest signal

Data-entry activity exploded again: person_added and source_submitted both roughly sextupled week over week (3→18 and 3→19). And of the 3 users who added a contact the week of Jun 7, 2 of them (67%) came back the following week to add more — early evidence that the handful of onboarded users are sticking around, not just trying it once.

Biggest concern

AI query usage is moving the wrong way while data volume grows. Query Asked fell from 7 to 1 (-86%), and the Person Added → Query Asked funnel conversion collapsed from 33% to 0% this week — the same drop-off flagged last week, now more pronounced even as 6x more data was added.

  1. 1. Bridge the gap between bulk data entry and the first AI query. This week person_added grew 3→18 (+500%) and source_submitted grew 3→19 (+533%), but query_asked fell 7→1 (-86%) and the Person Added → Query Asked funnel conversion dropped from 33% → 0%. Add an in-product prompt ("Ask Almura about the people you just added") that fires right after a burst of person_added/source_submitted events in a session, so the first query happens before the user leaves instead of becoming a separate, skippable step.
  2. 2. Fix active-user measurement — the gap has now persisted two reports running. This week, $identify-based WAU reads 1, but WAU measured from actual product usage (person_added, source_submitted, query_asked, graph_opened, profile_viewed) reads 3 — a 3x undercount, unchanged since last week's report. Until $identify (or a dedicated session_started event) fires on every app open rather than just first login, DAU/WAU/retention/signup numbers built on it will keep understating real usage. This should be an engineering fix this sprint, not a recurring caveat in next week's report.
Data gaps flagged, not skipped: no event for "relationship nudge surfaced/acted on" exists in the schema — nudge engagement still cannot be measured. New-signup counts via $identify show only 1 new signup this week vs 3 last week (lifetime total ~4 identified users), but person_added activity comes from at least 3 distinct people repeating week over week — the signup count is likely undercounted for the same instrumentation reason as WAU above, not a real drop in new users.
